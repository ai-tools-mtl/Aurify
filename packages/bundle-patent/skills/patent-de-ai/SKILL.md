# 专利交底书去 AI 味

## 核心铁律

**交底书面向专利代理人（专利律师），他们一眼能识别 AI 味。一旦读到套话，对整份交底书的信任度下降。** 去掉这些痕迹不是"润色"，是建立专业可信度的前提。

去 AI 味 ≠ 过度口语化。交底书仍须保持技术精确性与专业措辞——目标是"像人写的专业文档"，不是"大白话"。

## 六大 AI 味特征（逐条排查）

### 1. 套话转折词（必删）

以下词在正文出现时，删掉或改写：

| 禁用 | 替代做法 |
|------|----------|
| 更为关键的是 / 需要指出的是 / 需特别指出 | 直接陈述事实，不用引导句 |
| 换言之 / 换句话说 | 删掉，前文已说清则无需重述 |
| 值得注意的是 / 值得一提的是 / 需要注意的是 | 删掉，值得注意的事自然会被人注意 |
| 众所周知 / 毋庸置疑 / 不可否认 | 删掉，公知事实直接陈述，说明书另有公知常识认定渠道 |
| 这意味着 / 这表明 | 删掉，让读者自己得出结论 |
| 因此（句首 / 段末总结） | 仅在确有因果时保留，否则删 |

### 2. 巨长句（拆分）

**单句超过 150 字必须拆分。** 一句话最多承载三个信息量。拆分方法：
- 把"以及 / 同时 / 此外"连接的并列子句拆成独立短句。
- 把"从而实现……进而达到……最终使得……"的链式表述拆成 2-3 句。
- 长定语（"一种基于……的、能够……的、用于……的方法"）拆成"先说做什么，再说怎么做"。

### 3. 三连排比（消除）

**禁止三个及以上结构相同的短句并列堆砌。** 例如：
- ❌ "它高效、它稳定、它安全。" → ✅ "该方案在安全性上有显著改进（见有益效果 1）。"
- ❌ "不仅提升了效率，还降低了成本，更增强了可靠性。" → ✅ 直接陈述具体改进点，每个对应一个量化依据。

### 4. 总结句喂饭（删除）

**段末禁止用"这意味着……""因此本发明……"做总结。** 让事实陈述本身说话，代理人能自己归纳。技术结论应放在"有益效果"章节，用三段式（见 patent-effect-contrast 技能）呈现，而非每段末尾重复。

### 5. 句式单一（交替）

通篇长句或通篇短句都是 AI 痕迹。**长句后接短句（≤15 字）作强调，再接中等句展开**，形成自然节奏。例如："该模块负责凭证托管。它不直接参与加密运算，仅在被调用时按需释放密钥。"

### 6. 教科书定义（移除）

**背景技术章节禁止用"XX 是指……""XX 被定义为……"的教科书口吻。** 背景技术应从具体使用场景讲起（用户做了什么 → 遇到什么问题），让代理人建立画面感。精确定义留给"技术方案"章节。

## 章节语言水位（按章节调风格）

不同章节的语言要求不同，一刀切会出错：

| 章节 | 语言水位 | 要点 |
|------|----------|------|
| 背景技术 / 现有技术缺点 | 专业平实 | 场景化叙事，口语但不随意，无套话 |
| 技术方案 / 技术领域 | 精准严谨 | 术语精确，逻辑链清晰，可适度书面 |
| 缺点标题 / 效果标题 | 生动直白 | 一句话点明，避免"一种改进的……"模糊标题 |

## 英文术语首次翻译

**英文术语首次出现必须给中文翻译，格式：`中文译名（English Term，缩写）`。** 后续用缩写或中文。例如：
- 凭证托管组件（custodian）
- 代理重加密（Proxy Re-Encryption，PRE）

不要假设代理人熟悉所有英文术语缩写——首现不译会制造阅读障碍。

## 自检程序（工具把关，不靠自觉）

每章起草或修订后，把正文传入 `patent_prose_lint` 工具自检：**error 清零**该章才算完成（套话词、超长句、三连排比是 error；段末总结与教科书定义是 warning，原则上也要清）。工具是六大特征中可机器检测部分的确定性把关，与权利要求的 patent_claims_lint 同款纪律。

## 自检清单（生成后逐条过）

- [ ] 全文搜索套话词表，确认零命中或仅在有真实因果处保留
- [ ] 最长句 < 150 字
- [ ] 无三连及以上排比
- [ ] 段末无"这意味着/因此"式总结
- [ ] 句式有长短交替，非全长或全短
- [ ] 背景技术无教科书定义，从场景切入
- [ ] 英文术语首现均带中文翻译
