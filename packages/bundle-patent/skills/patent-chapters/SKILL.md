# 章节撰写策略

每章先读 `chapters/` 对应文件的当前内容与 `brief.md` 对应维度，再按本章策略撰写。范例均为通用化脱敏写法（技术内容抽象为"某发明/某系统"），学其结构与句式，不照抄内容。

## 各章策略

### 名称（01-name.md）

- **目标**：提炼一个清晰、准确的发明名称。
- **引导问题**：这个发明最核心的功能是什么？应用在什么领域？是产品、方法，还是两者结合？
- **输出格式**：名称 = <技术领域> + <核心特征> + <类型>。
- **完成判定**：名称 ≤25 字，包含技术领域和核心特征。

### 所属技术领域（02-field.md）

- **目标**：明确发明所属的技术领域。
- **引导问题**：属于哪个技术领域？涉及哪些专业技术分类？
- **输出格式**：一段简短的技术领域说明。
- **完成判定**：明确指出技术领域和大类。

### 背景技术（03-background.md）

- **目标**：描述现有技术的现状和不足。
- **引导问题**：目前这个领域有哪些现有技术？存在什么问题或不足？为什么需要改进？
- **输出格式**：现有技术描述 + 存在的问题。
- **完成判定**：至少描述一种现有技术及其不足。
- **范例**：随着某技术的发展，某类系统在应用中发挥重要作用，但其管理仍存在挑战。现有技术（如方案 A、方案 B）虽在一定程度上解决了问题，但在动态变化的场景下显得过于静态。例如，在某实际场景中，采用方案 A 的命中率可能从正常时期的 85% 降至 60% 以下。此外，现有方案还存在实现复杂、性能开销大、难以可靠实施等问题。
  写法要点：先述现有技术现状，再点出不足，最好用具体数据佐证不足的严重性。

### 技术问题（04-problem.md）

- **目标**：明确发明要解决的技术问题。
- **引导问题**：针对什么技术问题？解决它的意义是什么？注意：陈述的是**技术问题**而非商业/市场问题——专利法只保护技术方案的改进。
- **输出格式**：发明目的与技术问题的清晰陈述。
- **完成判定**：明确指出要解决的技术问题。
- **范例**：针对上述现有技术的缺点，本发明旨在解决以下技术问题：① 提高 X 性能和资源利用率，通过引入某机制实现 Y 的精确分类，从而提高命中率；② 改善 Z 一致性，优化数据更新策略，减少不一致风险。
  写法要点：必须呼应「背景技术」点出的不足，把每个技术问题对准一个不足；且陈述的是技术问题（如何实现/如何优化），不是商业问题（如何赚钱）。

### 发明内容（05-solution.md）

- **目标**：完整描述解决技术问题的技术方案。
- **引导问题**：方案的整体结构/流程是怎样的？有哪些关键组件/步骤、如何配合？每个关键组件具体解决哪个子问题？有没有替代实现方式？应结合附图阐述——若有系统框图、流程图，逐部件/步骤对照图说明。
- **输出格式**：整体架构 + 关键要素 + 工作原理。
- **完成判定**：至少覆盖结构、流程、关键要素三个维度，且必须显式呼应「技术问题」章节的表述。
- **范例**：为解决上述技术问题，本发明提出一种基于某机制的系统，其特征在于包括：核心计算模块（负责动态评估，对应解决技术问题①）、分类存储模块（基于计算结果分层存储）、策略管理模块（执行动态调整）。各模块协作流程为：计算模块产出热度信息 → 分类模块据此分层 → 策略模块动态调整。系统结构如附图所示。
  写法要点：① 开头「为解决上述技术问题」显式呼应 problem 章节；② 列出关键组件时标注其对应的子问题；③ 说清组件间协作流程。

### 有益效果（06-effect.md）

- **目标**：阐述发明带来的有益效果。
- **引导问题**：相比现有技术有什么优势？有哪些具体效果（性能/成本/效率）、能否量化？每个效果与方案的哪个组件直接相关？
- **输出格式**：具体、可量化的效果陈述；三段式写法见 patent-effect-contrast skill。
- **完成判定**：至少描述一个有益效果并与技术方案对应，尽量给出可量化数据。
- **范例**：本发明通过上述技术方案，实现了以下有益效果：① 通过核心计算模块的动态评估，相比传统方案命中率提升约 20%（可量化对比）；② 通过分层存储策略，存储空间利用率提升，访问延迟降低（对应分类存储模块）；③ 系统具备良好的横向扩展能力，能够应对负载增长。
  写法要点：每个效果都要与技术方案的某个组件对应，尽量给出量化数据或对比基线。

### 关键点与保护范围（07-key-points.md）

- **目标**：提炼发明的关键点与欲保护的技术范围。
- **引导问题**：哪些是区别于现有技术的关键特征（必要技术特征）？哪些部件/步骤组合构成欲保护的方案？哪些是核心创新点，去掉就不再是本发明？（独立权利要求的根基）哪些是优选/附加特征，可写成从属保护项？每个关键点对应方案的哪个组件？
- **输出格式**：逐条列出：关键点N：<特征>（对应方案组件/解决的技术问题）。
- **完成判定**：至少提炼一条欲保护的关键技术特征，并与技术方案组件对应。
- **范例**：本发明的关键点与欲保护范围如下：① 一种基于某机制的访问控制系统，其特征在于包括动态评估模块与分层存储模块（对应技术方案核心组合，区别于现有技术的静态策略）；② 根据关键点①所述系统，其特征在于评估模块按热度阈值动态分类（从属保护项，优选特征）；③ 根据关键点①所述系统，其特征在于策略模块根据分类结果实时调整（从属保护项，进一步限定）。
  写法要点：先写最核心的独立保护项（去掉即不构成本发明），再用「根据关键点①所述…其特征在于…」展开从属保护项；每条都要与技术方案的具体组件对应，便于代理人据此撰写权利要求。

### 实验验证（09-verification.md，涉及实验或量化效果的项目必备）

- **目标**：把"为什么本方案有效"讲成完整的证据故事——针对什么事情、普遍的解决方式、遇到的问题、本专利如何解决、解决效果，五段依次推进。
- **引导问题**：要验证的是什么能力/场景？业界对此普遍采用什么做法（基线）？普遍做法在什么条件下出问题？本专利的方案针对该问题做了什么 differently？实测/论证的效果差多少？
- **输出格式**：五要素结构——① 针对什么事情：一句话点出验证对象与场景；② 普遍的解决方式：现有基线做法简述（与背景技术呼应，可引用 reference/prior-art.md 的对比文件）；③ 遇到的问题：基线在该场景下的具体短板；④ 本专利如何解决：本方案的关键机制如何消除该短板（与发明内容呼应）；⑤ 解决效果：量化对比结果，**每个数字都必须能溯源到一条 experiments/ 的运行记录**（无实验项目的定性论证则引用公开数据或逻辑推演，并注明依据）。
- **完成判定**：五段齐全；效果段的每个关键数字都能在 run-log 中找到对应运行；实验结果图（figures/ 的图N）已插入并与文字对应。
- **范例**：针对大规模分布式系统中的任务静默丢失问题（针对什么事情），现有系统普遍采用周期性全量对账来兜底（普遍的解决方式），但全量对账在任务量增长时对账窗口拉长、丢失恢复延迟随规模线性上升（遇到的问题）。本发明采用增量状态指纹机制，仅对变化分区的指纹做一致性校验（本专利如何解决）。在某 N 节点仿真环境下实测，静默丢失的恢复延迟从全量对账的 2419ms 降至 309ms，校验开销下降约 76%（解决效果；数字出自实验运行记录）。
  写法要点：五段是叙事链不是问卷——每段承接上一段的结论；「普遍方式」与「遇到的问题」要具体到可反驳的程度（有公开号/公开数据支撑最佳）；效果数字与实验图一一对应，禁止写无运行记录支撑的数字。

### 附图（08-drawings.md）

- **目标**：描述附图内容及图注。
- **引导问题**：有哪些附图？每张图展示什么？用一两句话描述每张图的内容。
- **输出格式**：图N：<图的内容描述>。
- **完成判定**：每张图有对应的图注说明；设计规范见 patent-figure-design skill。

## 修订纪律

- 用户直接编辑过文件后，先读文件再改，不要凭记忆覆盖； diff 要让用户能逐处确认。
- 章节间引用保持一致：方案改了，问题/效果/关键点的对应关系同步更新。
- 章节文件只保留交底书正文本身：起草期的核对结论与过程注释（如名称结构拆解、字数统计、对照检查记录）写进会话回复或 `review/`，不要写进章节文件——导出会把这些注释原样带进交付文档。
