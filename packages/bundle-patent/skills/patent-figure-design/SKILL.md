# 专利交底书附图设计原则

本技能管"图怎么设计才简洁好懂"——图序怎么规划、每张图画什么、标注怎么写。适用于规划交底书的附图结构与撰写「附图说明」章节。

注：本技能管设计原则与图类纪律。三种经典图型（总览矩阵/架构分组块/步骤流）用 drawio 绘制并经 `render_drawio_figure` 工具渲染为 PNG；本技能之外的图型（时序图、状态机等）改由 `diagram-design` 技能按下方「扩展图型」一节的纪律绘制。

## 核心原则（不可违背）

### 1. 黑白极简风格

专利附图不是彩色营销图。**全部使用黑白配色**，禁彩色填充、禁渐变色、禁彩色图标。

- ✅ 纯黑白，用线宽区分层级（关键单元粗线、普通单元细线）
- ✅ 虚线用于辅助数据流、可选流程、说明框
- ❌ 禁止灰色背景块、彩色填充、彩色图标

### 2. 总图先行，逐层深入，图类形态互不混淆

**第一张图必须是流程总览图**，让读者（专利代理人）5 秒内看懂全流程。后续图逐步展开细节。

图序规划模板：
```
图1  流程总览图    —— 阶段×实体矩阵，最高层视角
图2  系统架构框图  —— 实体 + 内部单元 + 数据流
图3  核心方法流程  —— 主权利要求对应的步骤流
图4+ 增强/变体流程 —— 各从属权利的独立流程
```

**每种图有各自的形态，不得混用**——把总览图画成步骤流、把架构图画成流程图，读者就无法凭版式一眼识别图类：

| 图类 | 形态 | 视觉特征 |
|------|------|----------|
| 流程总览图 | 阶段×实体矩阵（泳道） | 实体作带标题栏的泳道列（或表格式行列），阶段作行，动作格沿对角分布，周期回路箭头绕图外缘 |
| 系统架构框图 | 分组块 | 组框（组名置顶）内嵌成员框，组间用少量带名箭头表达数据流，告警等辅助通道用虚线 |
| 方法流程图 | 竖排步骤流 | 圆角矩形步骤 + 菱形判断自上而下，主流程实线、回落/告警等辅助路径虚线 |

### 3. 中文标注，消除英文

所有实体名、步骤名、分支标签必须用中文。首次出现的英文缩写可附带在括号里（如"凭证代管方（Broker）"），后续仅用中文。

- ✅ "凭证所有者""凭证代管方""代理方"
- ❌ "Owner""Broker""Agent B"
- 公式符号（如 `rk`、`CT_O`）可保留原样，因其在正文中有定义

### 4. 一图一事，拒绝超长

单张图的纵向内容不超过 5~6 个主要步骤块。如果流程有 7+ 步骤，拆成两张图。

- 总图：阶段 × 实体矩阵，一屏看完
- 分图：每张 ≤ 6 个步骤块，含 1 个决策点

## 目录约定（figures/）

figures/ 目录的布局是纪律，不是建议——文档插图、导出器、项目面板都只认最外层的 PNG：

```text
figures/
  图1.png 图2.png        # 最外层只放最终插入文档的 PNG 成品
  source/                # 可编辑源：.drawio、diagram-design 的 .html 等
  tmp/                   # 中间产物：预览图、格式转换的过渡文件，用完可清
```

- 绘制时源文件一律写进 `figures/source/`；用 `render_drawio_figure` 渲染时，源在 `source/` 下成品自动落到 figures/ 根，无需手工挪动。
- 最外层不得出现 `.drawio`、`.html`、`*-preview.png` 之类的源文件与中间产物；临时对比版、导出过渡文件一律进 `figures/tmp/`。
- 定稿文件名 `图N.png`（推荐）或 `图N-名称.png`——导出器按 `图N` 前缀收集成品，其余命名不进交付文档；编号在图序规划定下后保持稳定，重画不换号。

## 绘制程序（从模板起笔，不从空白画布起笔）

本技能 `assets/` 下带三个骨架模板，几何坐标经过视觉验收验证（连线各走各的通道、分点进入目标框）：

| 模板 | 适用于 |
|------|--------|
| `assets/模板-总览矩阵.drawio` | 图1 流程总览（阶段×实体矩阵） |
| `assets/模板-架构分组块.drawio` | 架构图（分组块+登记表+判定器+两分支） |
| `assets/模板-步骤流程.drawio` | 方法流程图（椭圆起点+两道判定+双路径+汇合结果） |

绘制程序：把对应模板复制进 `figures/source/` 改名为 `图N-名称.drawio`，**替换文字内容、按需增删行列/分支，不改动走线几何**——模板的连线通道与拐点是验证过的，重画走线是线段重叠的主要来源。确需新增连线时，按下方「连线纪律」画，并照常过全部验收门。

### 连线纪律（画每条线时遵守，不是渲染后再查）

drawio 的自动布线（`edgeStyle=orthogonalEdgeStyle` 不带锚点时）会自由生成拐点、随意搭接同道线——「线突然转个弯」「两段线重叠」都源于此。画线时遵守：

1. **每条连线显式写两端锚点**：`exitX/exitY`（源框）与 `entryX/entryY`（目标框）必写（0~1 相对坐标；如 `exitX=0.5;exitY=1;entryX=0.5;entryY=0` = 从源框底边中点到目标框顶边中点）。没写锚点的线交给引擎自动布线，拐点不受控——这是头号禁忌。
2. **通道布线**：水平线段走行与行之间的空隙（统一 y 坐标），垂直线段走列与列之间的空隙（统一 x 坐标）；同向多条平行线**各走各的通道**，相邻通道错开 ≥16px，绝不共用同一坐标。
3. **拐点显式手写**：需要拐弯的线用 `Array as="points"` 的 `mxPoint` 写明每个拐点坐标，拐点**落在框外的通道上**——绝不落在任何框的边界内，也不与别的线的拐点共用坐标；多条箭头进入同一框时分点进入（entryX 各不相同），不叠在同一个进入点。
4. **布局先画网格再放框**：动笔前先在草稿上定行高列宽（如行距 120px、列距 200px），所有框对齐网格、连线通道用行/列间隙——框随手放、线绕着框拐，必然产生重叠与奇拐。

### 三级验收门（画完一图依次过，全过才算定稿）

1. **几何自查（机器门）**：调 `lint_drawio_figure` 工具读 drawio 源——它逐条检查锚点缺失、拐点入框、拐点共用、共走廊平行线；有 error 必须改源重查，warning（如个别无锚点边）要么补锚点要么确认无碍。
2. **渲染即复检**：`render_drawio_figure` 渲染前会再跑同一套几何检查，**有 error 直接拒绝渲染**并退回修改清单——所以第 1 步不过，渲染这一步也过不了。
3. **视觉验收（subagent 门）**：渲染成 PNG 后派 subagent 用 `read_image` 按下方检查单逐项验收——几何检查管结构，视觉验收管布局美观与语义正确，二者不可互相替代。

## 渲染验收门（subagent 强制，合格才保留）

渲染成 PNG 只是草稿。**每张图渲染后必须派一个 subagent 打开渲染成品做视觉验收，验收通过才允许作为定稿保留**——这一步不可省略、不可用绘制者自查代替：

1. **为什么必须是 subagent**：绘制者对自己刚写的布局有盲区——自查能挑出字号配色这类显性问题，恰恰漏掉线段交叉、贴框、箭头歧义这些结构性毛病；subagent 拿到的只有成品图，以旁观者视角逐项过检查单。
2. **验收方式**：派 subagent 用 `read_image` 打开 figures 根（或 tmp/）里的渲染成品，按下方检查单逐项给出 通过/不合格+具体位置 的结论；一张图一条结论，不许"整体看起来没问题"式的笼统放行。
3. **检查单**（任何一项不过即不合格）：
   - 连线不交叉、不重叠、不贴框不穿框：正交线各走各的通道，同向多股线错开坐标留出间距；多条箭头进入同一框时分侧或分点进入，不共用同一段线；
   - 无游离拐点：拐弯都发生在框外的通道上，拐点不在框内、不贴框边、不与他线拐点重合；每条线的路径是"沿通道走直角"而非绕开障碍的即兴折线；
   - 箭头指向与流程逻辑一致；分支标签（是/否等）紧邻自己对应的出口，不压线不压字；
   - 文字无溢出框外、无互相遮挡；标注在空白处；
   - 黑白无彩、中文标注、全图同族同字号、图内无图号图题；
   - 版面均衡，无大面积空白或一侧挤压。
4. **不合格 → 改源重渲 → 再验收**，循环到通过为止；迭代稿直接覆盖，不产生"图N-v2"这类副本。通过前该图不算定稿，不得进 08 章、不得进导出。
5. 向用户报告附图完成时附验收结论：每张图一行（subagent 验收通过 / 迭代 N 次后通过）。

## 图内文字与标注规范

- **图内不绘制图号与图题**：不要画"图1""图2"等编号或标题文字——附图编号由文档排版（附图说明章节、说明书附图页）在插图时统一标注，图内带号既冗余又会与排版冲突。
- **全图文字同族同字号**：同一张图内所有文字用同一字体族、同一字号，**字重是唯一允许的差异**——仅泳道标题、组框名等结构标题加粗，正文与标注一律常规体；同一框内混排两种字体风格即不合格。
- **连线标注放空白处**：不压框体、不穿其他文字、不与线重叠；放不下就缩短标注（如"分区状态"够用时不用"分区状态（实测 PPFD、温度、冠层图像）"），数据明细留给正文。
- **少用图内注释块**：解释性小字能省则省，注释内容属于正文与「附图说明」章节；确需保留时置于无连线经过的空白区。

## 流程图元素规范

无论用何种工具绘制，流程图元素应遵循统一约定：

| 元件 | 约定 |
|------|------|
| 开始/结束 | 椭圆/圆角框 |
| 处理步骤 | 圆角矩形 |
| 判断/决策 | 菱形，含两条出口（通过/不通过） |
| 主流程箭头 | 实线 |
| 辅助/可选流 | 虚线 |
| 说明文字 | 小字号，同族同色，不作强调 |

**决策菱形必须包含两条出口**：通过路径向下，拒绝/异常路径向侧面。

## 扩展图型：时序图、状态机等（diagram-design 技能）

需要的图不属于上表三种经典形态时（典型：时序图、状态机、部署图、依赖图），**加载 `diagram-design` 技能**绘制：先按其 `references/semantic-patterns.md` 选行为模式，再按对应 `references/type-*.md` 的版式语法产出自包含 `.html`（内联 SVG）。经典三形态仍按本技能用 drawio 画；同一份交底书里两套来源并存，图类凭版式肉眼可分。

用 diagram-design 画专利附图时，以下纪律**覆盖**其编辑风格：

1. **皮肤固定为单色 profile**：首次使用时把本技能 `assets/cnipa-monochrome.md` 原样复制为 `~/.diagram-design/profiles/cnipa-monochrome.md`，并在项目根建 `.diagram-design` 标记文件（内容仅一行 `profile: cnipa-monochrome`）。此后其 style-guide 门禁自动解析到黑白皮肤，**不得**在专利项目里走品牌引导问答。
2. **本技能的图内纪律全部沿用**：黑白无彩、中文标注、同族文字且字重是唯一差异、图内无图号图题、一图一事（纵向 ≤6 个主要块）、连线标注不压框不穿线。
3. **静态输出**：禁用其动画能力；`.html` 源存 `figures/source/`（如 `图6-时序.html`），预览等中间产物放 `figures/tmp/`，最终 PNG 落 figures/ 根；图号仍由文档排版在插图时统一标注。
4. **数量克制**：扩展图型按需增补，不挤占图1总览与图2架构的位置——总览图永远是图1。

## 插图纪律（图号与图注）

把 PNG 插入交底书或申请文件时：

1. **图号在图下方**：`图N` 标注置于图片下方居中——不放图上方，更不进图内（图内画图号是本技能明令禁止的）。
2. **编号与附图说明章节一一对应**：插图前先读 `chapters/08-drawings.md`，图N 的内容必须与该章"图N 为……"的描述一致；发现不一致时，或按实际图内容修订章节，或重绘图，不许带着错位交付。
3. **图下文字轻改写**：图下需要带一句说明时，对章节原句换句式、删冗词地**轻改写**——不逐字照抄「附图说明」章节原文，也不偏离其语义；不需要说明时只写"图N"。

## 附图说明章节撰写

「附图说明」章节应简洁列出每张图的名称与作用，与正文章节呼应：

```
图1 为本发明所述方法的流程总览图；
图2 为本发明系统的架构框图；
图3 为本发明核心方法的步骤流程图；
图4 为本发明某增强实施例的流程图。
```

步骤编号须与正文「系统流程说明」的 S1-Sn 对应，便于代理人交叉定位。

## 检查清单

- [ ] figures/ 最外层只有最终 PNG；源在 source/、中间产物在 tmp/
- [ ] 每条连线显式写了 exit/entry 锚点；拐点手写且落在框外通道上；平行线通道错开 ≥16px
- [ ] 每张图经 `lint_drawio_figure` 几何自查（零 error）——渲染工具会再拦一次
- [ ] **每张图经 subagent 视觉验收通过后才保留**（连线不交叉不重叠不贴框、无游离拐点、箭头正确、不压字）
- [ ] 图1 是流程总览图（阶段×实体矩阵或等效高层视角）
- [ ] 各图形态互不混淆：总览=矩阵/泳道，架构=分组块，流程=步骤流，肉眼可分
- [ ] 非经典三形态的图（时序/状态机等）经 diagram-design 绘制：单色皮肤、无动画、产物为 figures/ 下的自包含 .html
- [ ] 全部黑白配色，无彩色填充
- [ ] 全部中文标注，英文缩写仅在首次给出
- [ ] 全图文字同族同字号，仅结构标题加粗；图内无图号、无图题
- [ ] 连线标注不压框、不穿线、不压字
- [ ] 单张图纵向 ≤ 6 个主要步骤块
- [ ] 步骤编号与正文 S1-Sn 对应
- [ ] 箭头区分主/辅（实线/虚线）
- [ ] 决策节点包含两条出口（通过/不通过）
- [ ] 「附图说明」章节列全所有图，与正文呼应
- [ ] 插图时图N 在图下方居中，编号与「附图说明」一一对应；图下文字对章节原句轻改写
