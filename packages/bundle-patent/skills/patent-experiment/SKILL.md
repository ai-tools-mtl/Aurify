# 仿真实验纪律：可复现、可溯源、不编造

计算机类专利的有益效果需要数据支撑。实验的价值在于**可复现**（换台机器重跑得到同样结论）与**可溯源**（交底书里每个关键数字都能指到一次运行记录）。本技能管"实验怎么做、产物放哪、数据怎么进正文"——实验的科学设计（对比对象、指标选择）属于 patent-effect-contrast 的效果对比框架。

## 目录约定（experiments/）

每个实验是 `experiments/` 下一个独立目录，互不共享代码：

```text
experiments/
  throughput-baseline/     # 一个实验一个目录，kebab-case 命名
    run.py                 # 入口脚本（约定名 run.py；非 Python 实验见下）
    requirements.txt       # 依赖清单：镜像预装栈之外的依赖都写这里
    README.md              # 三行内说明：实验目的、怎么跑、结论指向哪次运行
    data/                  # 输入数据：公开数据集文件或标定参数说明，不随运行变化
    results/               # 全部运行产物：输出数据、日志、图、运行记录 run-log.md
```

- 实验脚本只写进 `experiments/<slug>/`，**不得**散落在项目根、chapters/ 或 figures/ 下。
- `requirements.txt` 只列镜像预装栈之外的依赖；预装栈见 `run_experiment` 工具说明（numpy/scipy/pandas/matplotlib/openpyxl）。
- `command` 参数只接受带普通参数的单个 `python`/`python3` 调用（如 `python run.py`、`python -m pytest -q`），不得携带 shell 运算符（`;` `&` `|` `` ` `` `$` `(` `)` `<` `>`）——它在整个项目的读写挂载上执行，白名单是硬约束；确需非 Python 命令（Node、C++ 等）时，请用户设置 `DSH_EXPERIMENT_ALLOW_ANY_COMMAND=1` 后再用，并在实验 README 里写明理由。

## 执行通道

| 通道 | 用途 | 纪律 |
|------|------|------|
| `run_experiment` 工具（docker） | **正式出数**——要写进交底书/申请文件的数据 | 唯一认可通道；运行记录自动落档 |
| bash/pwsh（宿主沙箱） | 探索性调试——验证思路、快速迭代脚本 | 产物只算草稿；转正前必须用工具重跑一次 |

- 工具不可用（会话未启用 MCP 服务）时，明说并给出启用方法（同 patent-services 的启用说明），**不要**静默降级为本地跑完就当正式数据。
- docker 不可用（未装/未启动 Docker Desktop）时，工具会报错给指引；此时可以本地调试，但正式出数必须等工具可用后重跑。

## 数据来源：公开优先，仿真有据

实验数据按以下顺序取用，**按序选择，不许跳级**：

1. **公开数据集优先**：优先选有出处、可获取的公开数据集（HuggingFace Datasets、Kaggle、UCI、政府数据开放平台、论文基准数据集等）。数据集名称、机构、版本/年份、获取方式写进实验 README.md；数据文件放 `data/`，不与运行产物混放。
2. **无合适公开数据集 → 检索真实情况再仿真**：先检索真实场景为仿真标定——对比专利里的应用场景描述（`search_cn_patents` 命中即真实需求的线索）、行业报告、论文的实验设置与参数量级（能 web_fetch 就 fetch 原文）。仿真参数标定到真实量级，每个关键参数注明依据来源；确实无据可依的假设参数，明确标注"工程假设"。
3. **禁止凭空造数**：没有出处支撑的参数分布、拍脑袋的"典型值"不进实验，更不进交底书。

数据来源说明随实验留档（README.md 或 `results/data-source.md`）：用了什么数据、从哪来、仿真参数的依据清单。效果章引用数据时交代数据基础（"基于公开数据集 ××"或"按 ×× 报告的场景参数仿真"），显著增强可信度。

## 结果与运行记录

`run_experiment` 每次运行自动向 `experiments/<slug>/results/run-log.md` 追加一条记录（时间、镜像、命令、退出码、输出尾部）。纪律：

- **不删不改 run-log.md**——它是数据出处账本；重跑产生新记录而不是覆盖旧记录。
- 实验脚本自身写产物只写 `results/`（数据文件、图、日志），不写实验目录其他位置，更不写项目其他目录。
- 向用户汇报实验结果时，带上运行记录位置（如"见 experiments/throughput-baseline/results/run-log.md 的 2026-09-17T… 记录"）。

## 数据进正文

- 交底书效果章（07-effect）或申请文件引用的**每个关键数字**，必须能溯源到 experiments/ 下的一次运行记录。写进正文时在会话里说明出处；正文本身保持散文体，不放运行日志。
- **禁止编造**：没有对应运行记录的数字不进正文。用户口头给的参考数据标注来源后再引用。
- **凡正式出数的实验必须配结果图**——数字进了正文（效果章、有益效果、具体实施方式）而没有任何实验结果图进附图，视同未完成：把结果图画进 `results/`（matplotlib 脚本入实验目录，读 results/ 的输出数据出图），定稿复制为 `figures/图N.png`（编号顺延既有示意图），08 章补"图N 为…"条目，随导出进交付文档。算法/性能类优化点的说服力在对比曲线与柱状图上，不画出来，审查人和代理人就只看到一表格裸数。
- 结果图同样走 patent-figure-design 的 subagent 视觉验收门：渲染不出的字体（豆腐块）、图例压线、黑白不可辨，验收不过不许进 figures/ 根。
- **出数后回填实验验证章**：把结果与关键数字写进 chapters/09-verification.md（五要素结构见 patent-chapters：针对什么事情、普遍的解决方式、遇到的问题、本专利如何解决、解决效果）——章里引用的每个数字都要能溯源到一条运行记录，无记录的数字不进章。

## 实验图规范（matplotlib）

数据图转附图时，除遵循 patent-figure-design 的黑白极简与图内无图号纪律外：

- 黑白区分系列：不同曲线用线型（实线/虚线/点划线）与标记（○□△）区分，**不用彩色**；填充区域用斜线纹理（hatch）不用灰色块。
- 中文标注：`run_experiment` 的镜像已配好中文字体（Noto Sans CJK SC）与 `axes.unicode_minus`，脚本无需再设置字体；本地跑时中文标签可能显示为方框，以工具重跑结果为准。
- 坐标轴、图例、单位齐全；图例不压数据线；同一张图内字号统一。
