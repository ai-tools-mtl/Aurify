# 说明书撰写（五段式）与申请书导出

## 启用前提：用户明确点名，才推进申请文件

本技能只在用户明确要求推进申请文件（"写申请文件""准备提交""出权利要求书""出申请书"这类点名表述）时启用。**"完成""写完""交付"这类未点名的指令默认指向交底书**——先走 patent-services 导出交底书 docx，再向用户确认是否继续申请文件。不要替用户把"完成交底书"理解成"完成专利申请"：申请文件是从交底书再加工的提交材料，跳过交底书交付等于没有交付。

推进前置（不满足先补齐，不满足就申请文件开工也是无源之水）：

- 交底书八章定稿，`exports/` 下已有交底书导出物（或用户明确表示不需要导出物）；
- 附图齐备且经 patent-figure-design 的 subagent 视觉验收通过。

## 目标

把交底书八章内容重组为符合审查指南结构的说明书（`application/description.md`）、说明书摘要（`application/abstract.md`）与权利要求书（`application/claims.md`，撰写程序见 patent-claims），再经 `export_application_docs` 在代理机构正式申请书模板上导出为提交格式的申请书 docx。**格式由模板承载，不由撰写者发挥**——不要手改导出物，要改就改 `application/` 源文件重导。

## 发明名称纪律

- 发明名称的正本是 `patent.yml` 的 `name`，导出物直接使用它。**导出前把名称定稿**：改名称先改 patent.yml，再导出。
- ≤25 字（专利名称一般不超过25字）。导出器对超字名称回 warning——收到就找用户定夺口径，不要自行缩写提交。写名称优先把发明点前置（如"绑定去中心化身份密钥的…"点出绑定机制），比"基于A与B的C方法及系统"式长枚举更容易压进25字。实测教训：一件 DID/VC 专利的31字枚举长名被迫改用27字短名口径，返工发生在导出之后。

## 五段结构

按以下固定顺序组织，段首使用标准段落名：

1. **技术领域**（← chapters/02-field.md）：一两句话，写发明所属领域与直接应用场景，不写背景。
2. **背景技术**（← chapters/03-background.md）：现有技术及其缺点，逐条与 `claims` 独权前序部分呼应；引证具体出处的（型号/专利号）保留，没有的用"现有方案"泛指。
3. **发明内容**（← chapters/04-problem.md + 05-solution.md + 06-effect.md）：三段式——"针对上述问题，本发明提供…"逐条对准缺点；随后**逐权项复述**：每条权利要求的技术方案在说明书中至少出现一次完整支持表述（权利要求的"说明书依据"）；最后有益效果逐条对应。
4. **附图说明**（← chapters/08-drawings.md）：逐图"图N为…"清单，图号与 figures/ 下的文件名对应。附图用的是文字标签而非数字标记时**不写"附图标记说明"段**——该段只承载"数字→部件名"映射，没有数字标记就没有映射可写，硬凑反而与图对不上。
5. **具体实施方式**（← 05/06 章的细节展开；有实验验证章的项目并入 09-verification.md 的实验叙事）：至少一个完整实施例（含参数范围），覆盖独权全部必要特征 + 主要从权各一个落地面；给出替代实现（"在另一实施例中…"）支撑权利要求的概括范围。实验数据在此以实施例效果的形式呈现（"在××条件下，……"），与 06 章口径一致、每个数字可溯源到 experiments/ 运行记录。

## 摘要（application/abstract.md）

- ≤300 字（非空白字符），写发明名称、技术领域、核心手段、主要效果各一句；
- 不得出现"附图说明"性内容和商业宣传语；
- 定稿前把摘要传入 `patent_claims_lint`（连同 claims）核对 A1（工具与传法见 patent-claims「撰写程序」第 5 步）。

## 撰写程序

1. 读 brief.md、chapters/ 全部八章、application/claims.md（若已起草）；未读不动笔。结构骨架从本技能的 [assets/骨架-说明书五段与摘要.md](assets/骨架-说明书五段与摘要.md) 起笔——占位槽全部替换为真实内容，不得把占位符带进成稿。
2. 按五段结构起草；发明内容段的逐权项复述与 claims 术语逐字一致（复制权项措辞后展开解释）。
3. 术语首现即译规则与交底书一致：中文译名（English，缩写）。
4. 应用 patent-de-ai 与 patent-writing-quality 规范（两技能均适用于说明书散文正文，权利要求书除外）；实施例中的量化数据沿用 06/09 章口径，不新增未经用户确认的数据。
5. 请求用户确认五段覆盖情况与实施例数量后收尾；更新 patent.yml status 为 `application`。

## 内容格式约定（导出器契约，源文件必须照此写）

这些约定是 `export_application_docs` 的解析契约，违反不会报错但会在导出物里变形：

- description.md 的五段用 `## `（如 `## 技术领域`），五段之下的实施例小节用 `### `（如 `### 实施例一`）；**标题不自带编号**——不要写 `## 一、技术领域`、`### 5.1 xxx` 这类前缀，导出器剥离它们并按模板样式重排。
- 公式行独占一行、用 `$$` 包裹（如 `$$K = H_{0}(K_{1} ‖ K_{2})　　(2)$$`），编号写在行内随文本居中导出；不要用图片公式或 LaTeX 块。
- 上下标写 `_{...}`/`^{...}`（如 `K_{1}`、`ρ·PK_{d}`、`2^{-Δt_{i}/τ_{0}}`），导出为真上下标；不要用 Unicode 上下标字符，字号不可控且检索不可用。
- 加粗写 `**…**`，导出保留加粗 run。
- abstract.md 是一段正文，不用标题层级。
- claims.md 每条权项一段：`1. `、`2. ` 起头，续行是同一段的可读性折行，不是新段落。源文件保留字面编号，导出器剥掉后由模板的自动编号列表续排——自行重排编号只会与模板编号叠加出错。

## 导出与验收门（subagent 强制）

0. 🔴 **导出门**：先按 patent-chapters「评估路径」重跑四角核对（技术问题↔发明内容↔有益效果↔关键点，附图描述与 figures/ 一致），发现不同步先修章节；再跑 `patent_claims_lint`（claims 全文连同摘要）确认零 error；最后向用户确认"即将导出正式申请书"且此后源文件未再改动——确认后被改动的源要重新确认。三条都满足才进第 1 步。
1. 调 `export_application_docs(project_dir, fmt="docx")` 导出（有 figures/ 成品时自动带摘要附图与说明书附图节）；工具不可用或报错时如实说明并停止，不手拼 docx 代替；
2. 核对返回信息：warnings 逐条处理（多余一级标题→修源文件；名称超字→找用户）；"内嵌附图 N 张"与 chapters/08 声明条数一致，零附图或缺图先修命名与渲染再重导；
3. 转 PDF 渲染成 PNG（LibreOffice `soffice --convert-to pdf` 或 Word COM），**派 subagent 逐页视觉验收**，派单附上 claims/description 源要点供核对。自查不算验收——撰写者对自己漏抄的段落是盲区。检查单：
   - 五节页眉正确（说明书摘要/摘要附图/权利要求书/说明书/说明书附图），页码每节重排；
   - 无乱码、无占位符残留、无交底书内容串场；
   - 权利要求连续自动编号、无字面 "N." 与模板编号叠加；
   - 公式居中、上下标为小号真上下标；
   - 附图完整居中、无拉伸变形，图号与 08 章一一对应；
   - 摘要页无图，摘要附图页只有图1。
4. 不过即改 `application/` 源文件重导，不得手改 docx。

## 完成判定

逐项对照文末「检查清单」，全部通过即视为完成——判定条目与清单一一对应，不在此重复罗列；清单之外唯一补充：每条权项在"发明内容"或"具体实施方式"有**可指认**的支持表述（不是语义近似，是能指出在第几段）。

## 修订纪律

- claims 变更后先改"发明内容"的支持表述，再考虑其他段；
- 用户手工编辑过 application/ 文件后，先读再改，diff 供逐处确认；
- 导出物上发现格式问题永远回源文件修——模板格式与源内容是两条独立的出错链，手改 docx 会让下次导出把修复冲掉。

## 检查清单

- [ ] patent.yml `name` ≤25 字且为用户确认的定稿口径；
- [ ] 五段齐全，段名用 `## ` 标准段落名，实施例用 `### `；
- [ ] 逐权项支持表述齐备，术语与 claims 逐字一致；
- [ ] 公式行 `$$…$$`、上下标 `_{...}`/`^{...}` 写法合规；
- [ ] 摘要 ≤300 字、四要素齐备、A1 通过；
- [ ] 附图说明与 figures/ 成品一一对应，无数字标记则不写附图标记说明；
- [ ] `patent_claims_lint` 无 error；
- [ ] 导出 warnings 清零或逐条向用户说明；
- [ ] subagent 视觉验收全页通过并附结论。

## 能力边界

- 模板格式合规≠通过实质审查：新颖性/创造性/公开充分由 patent-review 与代理人把关，导出物只是格式合格的提交底稿；
- 视觉验收只对渲染结果负责，不校验密码学常数、实验数据等技术事实的正确性；
- 摘要附图固定取图1：摘要附图想换图时改 figures/ 的图序，而不是改导出器。
